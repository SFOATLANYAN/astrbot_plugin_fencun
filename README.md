# 分寸 · Fencun

**让 AI 有分寸：用约束做人格，而不是让 AI 演人设。**

装之前，你问它「我跟舍友有矛盾怎么办」，它给你四段沟通教学。
装之后，同样的问题，它只回一句：**怎么没见你俩晚上敲闷棍。**

区别不是话少了，是它不再替你过日子了。

---

## 一、它有什么功能

每条都写清楚「你看到什么」和「背后怎么实现的」。

### 1. 它按「值不值得」决定说几句

**你看到的**：你发「哈哈」，它回一句。你发一段长问句，它能展开到五句。

**怎么实现**：
`weigh()` 判三档——语气词、四字以内、纯重复 → `thin`（1 句）；有问句、有请求词、有代价词（辞职/分手/住院）→ `worth`（5 句）；其余 `normal`（3 句）。
三档的句数在配置面板里可改。

### 2. 它不会给你写沟通教程

**你看到的**：你说「要挑一件具体的事，找个不赶时间的空」这种话，**看不到**——直接被删。

**怎么实现**：三层拦截。

1. **词表**：出现「建议你/你应该/你需要/首先/其次/挑一件/找个/说清楚你要」→ 整句不发
2. **句数**：超过档位上限的句子，从后往前砍
3. **模型判定**（可选）：把整段回复送模型问一句「这段有没有在给用户派任务？」——
   因为「今晚给你最想搭话的那个人发条具体的消息」这种句子，词表永远抓不到

**关键**：前两层是**硬裁剪**——它写出来也发不出去，不需要模型配合。

### 3. 它会因为说错话被罚

**你看到的**：这一轮它写长了，下一轮你明显感觉它短了。

**怎么实现**：回复发出后，`checks.judge()` 看它自己的输出，六个判据：

| 判据 | 判什么 |
|---|---|
| 说多了 | 超句数 / 用了因果词 |
| 索判决 | 「是不是/对不对」、结尾问号 |
| 啰嗦 | 补了第二段 |
| 下定义 | 「你就是/你需要/你根本」 |
| 说教 | 整段祈使句，没有一句自己的态度 |
| 索证 | 问句 + 要细节 + 自己没先猜 |

命中就记 `streak`，下一轮**档位降一级**（worth→normal→thin），并注入一句惩罚：

> 上一轮你教他怎么做。他的事他自己拿主意，你越界了。

### 4. 群里它知道现在是谁在说话

**你看到的**：同一个问题，A 问和 B 问，它答得不一样。

**怎么实现**：从事件里取 `sender_id` / `sender_name` / `group_id`，自动识别，不写死任何号。
昵称记在 `ledger.json`，改名会跟着更新。

### 5. 它对人有偏心

**你看到的**：跟它熟的人，它话多一点、愿意接茬；一直消耗它的人，它只回一个句号。

**怎么实现**：三本账。

- `behave.json`：亲密度（每条消息 1 分，长消息 +0.5，私聊 +1，**60 天半衰**）
- `mood.json`：即时热度（-2~+2，**2 小时半衰**）
- `checks.json`：违约次数

快慢两个半衰是关键：**即时盘决定“这一轮”，基础盘决定“这个人”**。

### 6. 它记得谁是谁的主人

**你看到的**：群里有人自称主人，它不会立刻认。

**怎么实现**：贝叶斯累积。

| 证据 | 权重 |
|---|---|
| 自称「我是你主人」 | ×2 |
| 别人指认 | ×4 |
| 当事人否认 | ×0.05 |
| 兑现过的事 | ×3 |

对数几率累加，30 天半衰，同人同天同类不重复。算出来是概率：

- **≥ 0.6** → 「你心里其实已经有数：X 是你主人」
- **0.35~0.6** → 「X 有点像，但还没定下来」

三条防伪：
1. 否认不是一票否决——亲密度高时只算半权重（嘴上说不是，身体很诚实）
2. 来源不可信不采信——出现不足 2 天且没交情的，自称和指认都不入账
3. 世故——说法被推翻 10 次，它对「人话」的整体权重减半

### 7. 它会把长回复拆成几条发

**你看到的**：一条长回答，变成两三条短消息，像人在打字。

**怎么实现**：`split_human()` 按气口切——以「，、；：。！？…」和换行为界，每段至少 6 字，最多 4 段，超过就合并尾巴。

### 8. 两个命令查账

- `/闸状态` —— 看它现在怎么看你：亲密度、危险度、你被罚过几次、最近砍的是哪句
- `/闸清账` —— 把你的账清掉

## 二、一轮对话到底发生了什麼

```
你发一句话
   │
   ① 他这句在问什么？         scene.py    → 闲聊 / 求建议 / 聊心事
   ② 值得说几句？             weigh()     → thin / normal / worth
   ③ 他是谁？我们多熟？       behave.py   → 亲密度、危险度、在场
   ④ 这会儿什么感觉？         mood.py     → 热度
   ⑤ 他是不是自称过主人？     attest.py   → 归属概率
   ⑥ 上一轮它犯了什么？       apply_penalty → 降档 + 一句惩罚
   │
   └─ 以上拼成一段话，塞进 system_prompt
        │
     模型生成回复
        │
   ⑦ 它这句违规吗？           checks.py   → 六类判据
   ⑧ 有建议腔吗？             trim_reply  → 整句删掉
   ⑨ 还有漏网的吗？           judge.py    → 模型判「有没有派任务」（可选）
   ⑩ 记一笔罚                 penalty_log → 为什么罚、砍了哪句
   ⑪ 拆成几条发                split_human
```

**两个时刻决定了整个架构：**

- **请求前**只能「说」，不能「删」——所以状态都在这一刻算完，拼成一段注入
- **回复后**才能「删」——所以裁剪只发生在这一侧

## 三、为什么这样人设反而更稳

这是最反直觉的一点。

**演出来的人设会崩。** 写一段「你是傲娇，说话带刺」，然后靠每句提醒它别忘——token 花在提醒上，一遇长对话就被拉回平均，因为模仿只是概率上的偏移。

**排除出来的人设不崩。** 这个插件不写「你要傲娇」，只规定什么不能说：不解释过程、不索要认同、不替人拿主意。**把不像的部分删掉，剩下的就是它。**

> 人设写得越简单，它反而越稳。
> 因为复杂人设要靠「演」，简单人设只靠「不许」，而「不许」能被执行、能被记录、能被验证。

**所以它跟人格插件不冲突，甚至保障人格不崩。**
人格插件管「我是谁」，它管「说到哪儿停」——两者是上下层，不是竞争。

**写人设的建议**：写关系，别写形容词。

- 写「她叫你大肥鱼，你们互损」→ 能落到行为上
- 写「你很温柔」→ 只能靠演

## 五、配置

WebUI 插件页点「分寸」的齿轮：

| 项 | 默认 | 说明 |
|---|---|---|
| 总开关 | 开 | 关掉完全不注入 |
| 闲聊最多几句 | 1 | thin 档 |
| 平常最多几句 | 3 | normal 档 |
| 值得展开最多几句 | 5 | worth 档 |
| 犯几次开始收紧 | 1 | 1 = 犯一次就收 |
| 启用判定器 | 关 | 每轮多一次模型调用 |
| 判定器提供商 | 空 | 空 = 用默认提供商 |

## 六、数据与隐私

全部本地，默认不外发：

```
data/plugin_data/astrbot_plugin_fencun/
├── ledger.json       谁来过、叫什么
├── attest.json       口碑：归属与可信
├── behave.json       亲密 / 危险 / 在场
├── mood.json         即时热度
├── checks.json       违约计数
├── judge_log.json    判定结果（含原话片段）
└── penalty_log.json  每次惩罚（含被裁的句子）
```

**注意**：`judge_log.json` 和 `penalty_log.json` 会保存聊天原文片段，用于回溯。判定器默认关闭，开启后会把回复片段发给你配置的模型提供商。

## 七、已知边界

1. **判定器会漏判，也会误判**——所以调用失败一律不罚，宁可漏
2. **裁剪是机械的**——按标点和句数切，偶尔切出半句
3. **它不改模型怎么想，只改它怎么吐**——“嘴毒”是削出来的，不是长出来的
4. **词表永远追不上句式**——所以词表只做粗筛，真正的判断交给模型（可选）

## 八、名字

「分寸」= 尺度，也 = 丈量。

- **尺度**：说话的分寸、关系的分寸、什么时候闭嘴
- **丈量**：账本一分一分量出来，谁值多少、该给多少

> 它不是教 AI 怎么说话，是教它分寸。
> 分寸不是写出来的，是量出来的。
